# ADR-006：最终证据与发现线索分层

日期：2026-09-01  
状态：已采纳

## 背景

一次藏知问答通常先用 `knowledge_search` 发现资料，再用
`knowledge_query_dataset` 查询实际贡献行。搜索命中的数据表目录片段和精确查询结果
可能来自同一文档并使用相同标题，但前者只是导航线索，后者才是回答的原始证据。
两者同时列在最终回答下方时会显示成重复来源，且点击后分别打开目录片段和数据行，
让用户无法判断哪一条真正支持答案。

真实搜索载荷中的目录片段以 `chunk.type = dataset_catalog` 标识，包含
`document_id + document_version_id + chunk_id`，但不一定包含 `dataset_id`；精确查询
则包含 `document_id + document_version_id + dataset_id + source_rows`。

## 决策

1. 在结构化证据中保留 `chunkType`，兼容顶层 `chunk_type` / `chunkType` 和嵌套
   `chunk.type`。
2. `chunkType === dataset_catalog` 且没有贡献行的证据定义为发现线索。旧载荷只有在
   同时缺少 `chunkId`、`chunkType` 且具有数据集身份时才使用结构回退。
3. 同一轮存在带 `source_rows` 的精确数据集证据时：
   - 发现线索带 `datasetId`，按 `documentId + documentVersionId + datasetId` 替代；
   - 发现线索不带 `datasetId`，按 `documentId + documentVersionId` 替代。
4. 分层只作用于最终 `cangzhi-evidence` 节点。工具过程卡仍展示搜索和查询步骤，便于
   排查检索过程。
5. 标题不参与判定。普通文档片段、非目录型数据片段以及不同文档或版本的证据不得
   因名称相同而合并。

## 影响

- 用户最终只看到能够直接打开贡献行的证据，不再看到同标题的数据表目录线索。
- 没有后续精确查询时仍保留目录线索，避免问答只有发现结果时完全失去来源入口。
- 对缺少 `dataset_id` 的目录线索采用文档版本级替代；这是由当前搜索接口身份信息不足
  决定的保守策略。若后端未来稳定返回 `dataset_id`，会自动使用更精确的三元组匹配。

## 验收

- 文档 6 / 版本 6 / chunk 59 的 `dataset_catalog` 搜索命中，与同版本 dataset 4 的
  12 行精确结果同时出现时，最终证据只保留 dataset 4。
- 工具过程卡仍可分别查看搜索和查询结果。
- 不同文档、不同版本、普通 chunk 以及只有目录线索的轮次均保持原行为。
