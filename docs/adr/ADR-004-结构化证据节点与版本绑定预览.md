# ADR-004：结构化证据节点与版本绑定预览

日期：2026-08-31  
状态：已采纳

## 背景

此前证据入口依赖两条不稳定路径：工具卡折叠内容，以及从模型最终回答中用正则提取
`document_id` / `dataset_id`。模型不写编号、改写格式或工具卡折叠后，用户就看不到
证据；即使按钮出现，工作台也打开当前最新版或数据表普通分页，而不是回答实际使用
的文档版本、片段和贡献行。

## 决策

1. 插件从 DSH 持久化的 `tool/call` 与成功 `tool/result` 事件中折叠
   `mcp__cangzhi__*` 的结构化结果，以 turn 为边界生成独立
   `cangzhi-evidence` Conversation Node。
2. 证据节点只接受可以追溯的身份：文档证据至少需要
   `document_id + document_version_id + chunk_id`；数据证据至少需要
   `document_id + document_version_id + dataset_id`，并保留
   `artifact_version`、`source_rows`、`columns` 与 `query_plan`。
3. 节点固定显示在本轮回答结束后，不依赖模型最终文本，也不占用仅悬停显示的
   assistant action 行。历史对话从原始事件重放时可重建同一证据列表。
4. 点击“查看原始证据”只调用藏知版本绑定的 `/api/v1/knowledge/evidence/*`
   接口。数据表只读取本次结果声明的 `source_rows`（最多 200 行），不以普通表格
   前 100/200 行替代；文档显示版本绑定章节、页码和原文件/版式预览入口。
5. 旧历史记录缺少 `document_version_id` 时显示“缺少版本信息”，禁止用最新版伪装
   成原始证据。回答文本正则仅保留给旧工具卡展示，不参与新证据节点。

## 影响

- Cangzhi 的 `knowledge_query_dataset` 响应需向后兼容地增加标题、文档版本和受控
  查询计划字段。
- 插件需要 DSH `uiConversation` 服务和 `conversation.chat.node` keyed slot。
- 插件本地开发应使用 `link:`，发布/复制安装应在版本更新后强制刷新 Profile，避免
  pnpm 的 `file:` 快照继续使用旧构建产物。

## 验收

- 最终回答是否写出 ID 不影响证据区出现。
- 点击数据证据看到的行号与工具结果 `source_rows` 一致。
- 文档更新后，旧证据不会静默跳到新版本。
- 无成功藏知工具结果的回答不显示伪造证据。
