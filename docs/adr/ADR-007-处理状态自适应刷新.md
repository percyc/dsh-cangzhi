# ADR-007：处理状态自适应刷新

日期：2026-09-01  
状态：已采纳

## 背景

DSH 管理中心此前只在打开或手动刷新时读取一次资料概览。后台任务在页面打开后启动
时，顶部处理队列会一直保持旧值。与此同时，藏知 `/api/system/status` 只读取当前
`DocumentVersion.processing_status`，会漏掉文档主体已就绪、但向量等派生任务仍在
运行的阶段。

## 决策

1. 当前知识空间的队列数字以分页读取的
   `documents/overview?include_processing=true` 中 `pipeline.overall_status` 为准。
2. 服务器状态由藏知按当前、未删除文档版本上的实时 `ProcessingJob` 聚合；多个任务
   行按文档版本去重，`processing` 优先于 `created` / `retry`，并保留旧版本状态字段
   的兼容回退。
3. 管理中心使用单飞、可取消的递归定时器轻量刷新，只请求资料概览和系统状态：处理
   中 3 秒、空闲 15 秒、页面隐藏 60 秒，失败时指数退避。
4. 初次加载、手动刷新或切换空间进行全量刷新时暂停并中止轻量轮询；轻量路径不得
   同步模型空间、重新读取分类或改变当前页签。
5. 资料概览必须按 `X-Total-Count` 取全，避免超过 200 份资料后队列数字和筛选结果
   被截断。

## 影响

- 外部页面或 Worker 启动的任务会在空闲轮询窗口内被发现，随后按 3 秒更新。
- 当前空间卡片展示当前空间的文档流水线状态；服务器状态展示管理员可见的全空间
  文档级队列，两者作用域不同，不应强求数字相同。
- 大型空间在处理期间会每 3 秒分页读取完整概览。若资料规模继续增长，应由后端增加
  仅返回运行中条目或聚合计数的专用接口，再替换全量分页轮询。

## 验收

- 任务运行时能观察到 `0 → 处理中 → 0`，无需手动刷新。
- 多个向量子任务只计为一个处理中资料；旧版本任务和已删除资料不计入。
- 工作区切换和全量刷新不会与轻量请求重叠，卸载时不会继续更新状态。
- Node 测试、后端处理状态测试、DSH preset 构建和产物语法检查通过。
