# ADR-002：知识空间和能力策略必须按 DSH 会话隔离

- 状态：部分实现（能力策略已实现，知识空间仍待实现）
- 日期：2026-08-31

## 背景

当前 Host 使用进程内的 `activeWorkspaceSlug`，MCP 代理通过请求头把它发送给藏知。多个浏览器用户或多个 DSH 对话共享同一个值，存在串空间风险。

## 决策

后续实现必须把以下信息绑定到 DSH 的 `sessionId` 或明确的用户身份上下文：

- 当前知识空间；
- 知识能力策略（开启/关闭）；
- MCP 请求头中的空间标识；
- system prompt 中的知识能力说明。

能力策略已经绑定到 DSH `sessionId`：Host 在 Agent 作用域隐藏 Cangzhi system prompt，并拒绝 14 个 Cangzhi MCP 工具；localStorage 只用于恢复界面显示，不是安全边界。知识空间仍使用进程级状态，下一阶段再迁移。

## 验收要求

- 会话 A 切换空间不会改变会话 B 的空间。
- 会话 A 关闭知识能力后，不能调用藏知 MCP 工具。（已实现；从下一次模型步骤生效。）
- 重载和恢复会话后，设置仍绑定原会话。
- 未提供会话身份时，界面必须明确显示降级范围，不能声称已完成隔离。
