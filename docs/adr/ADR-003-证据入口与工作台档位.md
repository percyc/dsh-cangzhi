# ADR-003：证据入口结构化 + 工作台宽度交互

- 状态：已采纳（宽度交互已按用户验证修订）
- 日期：2026-08-31

## 背景

工具结果卡片目前只对 `knowledge_search` 和 `knowledge_ask` 提供"打开来源证据/右侧预览"按钮，而 `knowledge_query_dataset` 的结果对象里其实已经带 `document_id` + `dataset_id`，却仍走 `resultPreview` 的纯文本路径，导致用户看到查询结果后无法一键跳到工作台预览，只能手工搜索。`answerEvidence` 也只靠正则从 `knowledge_ask` 的 answer 文本里识别引用，遇到模型用结构化 JSON 输出时无法可靠命中。

藏知工作台需要在不占用过多对话空间的前提下支持连续调整宽度。曾短暂加入"窄/标准/宽"和全屏按钮，但实际使用反馈认为它们与拖拽重复、增加顶栏视觉噪音，因此改回单一的拖拽交互。

## 决策

1. 工具结果卡片统一通过 `cangzhi-open-document` 事件向工作台派发来源证据，不再依赖脆弱正则：
   - 抽出 `src/client/lib/evidence.mjs`，提供 `idNumber`、`collectStructuredEvidence`、`dedupeEvidenceLinks`、`fallbackAnswerEvidence` 四个纯函数。
   - `EvidencePreview` 解析 MCP `content` / `structuredContent` / `result` 三层后递归收集 `document_id + dataset_id` 链接。`knowledge_query_dataset` 命中即展示最多 3 条去重来源，按钮文案统一为"打开来源证据 · 右侧预览"。
   - `answerEvidence` 改为先尝试把 answer 解析为 JSON 取结构化链接，再回退到《文档名》document_id … dataset_id … 的正则匹配，保留旧行为。
2. 工作台仅保留连续拖拽：
   - 通过 `clampWorkbenchWidth` 将桌面宽度限制在 360–760px，并把最终宽度写入 `cangzhi-workbench-width`。
   - 顶栏不再展示档位和全屏控件，只保留知识库管理与关闭按钮。
   - 移动端（max-width 760px）继续隐藏拖拽手柄，保留 DSH 已有折叠行为。
3. 最终回答的来源入口使用 DSH 原生 `conversation.chat.assistant-actions` 槽位，根据 `messageId` 获取当前回答文本并提取文档/数据集标识；命中后显示“来源”按钮，点击继续复用 `cangzhi-open-document`。

## 取舍

- 优点：证据入口同时覆盖工具卡和最终回答；工作台顶栏更简洁，宽度只有一套可预期的拖拽语义。
- 代价：不再提供一键档位和全屏；需要大范围阅读时由用户拖到 760px 上限。
- 旧 `cangzhi-workbench-width` 继续有效；历史 `cangzhi-workbench-size` / `cangzhi-workbench-fullscreen` 值不再读取。
