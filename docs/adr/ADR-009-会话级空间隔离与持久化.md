# ADR-009：会话级藏知知识空间隔离与持久化

- 状态：实现完成，Host 验证通过，浏览器验收待完成
- 日期：2026-09-07

## 背景

ADR-002 要求的会话隔离中，能力策略已绑定 DSH `sessionId`，但知识空间仍由进程级 `activeWorkspaceSlug` 共享：同一个 DSH 进程下所有对话的 `mcp__cangzhi__*` 调用都携带同一个 `x-cangzhi-workspace`。并发 A/B 对话无法各自检索；刷新 / 恢复会话或 Host 重启后，空间与能力开关也不会保持。通用 DSH MCP bridge（`cangzhi-mcp`）把整套 transport 绑定到一个 URL + 一套静态 header，无法把「正在执行的会话」传递到每次 `tools/call` 的请求上。

外部已确认事实：`/data/share/cangzhi/apps/api/api/mcp.py` 是 Stateless MCP Streamable HTTP adapter，`tools/call` 不要求先 `initialize`（表头明确标注 Stateless）；因此一次 `tools/call` 请求可独立携带工作空间，无需会话握手。

## 决策

1. **作用域工具覆盖 + 每次执行解析工作空间**（本实现采用的「作用域工具覆盖」路线）。Host 在每个 live agent 作用域注册 `mcp__cangzhi__*` 的 scoped 覆盖，其 `execute` 在**执行时刻**根据 `exec.agent.id`（沿 `session.header.parentSession` 向上继承）从持久化 store 解析该会话的工作空间，然后通过插件自己的回环代理发出 `tools/call`，并显式携带 `x-cangzhi-workspace`。scoped 注册天然 shadow 全局同名工具，所以模型只见本会话的覆盖；工作空间切换在**下一次调用立即生效**，无需重连。
2. **绝不停默回到进程级工作空间**。override 的 `execute` 在读不到执行会话时抛出「无法确定执行会话」；解析到「未绑定」时明确返回 `bound:false`（降级标记），客户端据此显示未隔离，绝不声称隔离。全局 `cangzhi-mcp` bridge 仍连 3081，仅作为无会话注解时的明确标注降级默认；scoped 覆盖的每次请求都显式带工作空间 header，mcpProxy 只在调用方未携带时回退进程默认，从而保证隔离不会被 wire 覆盖。
3. **竞态处理**：
   - agent 先于 `cangzhi-mcp` 注册 / 重连注册 → override 以 0 个工具注册；监听 `tools/change` 用签名比对，Cangzhi 工具集变化时对所有「开启」会话的覆盖做 dispose + 重新注册，指向最新全局 schema 集。
   - 全局工具消失 → 相应覆盖被移除；bridge 尚未连接时无工具可调用，因此不存在「静默回落」路径；一旦恢复即带正确会话工作空间重新注册。
   - plugin 启动时主动对 `ctx.agents.list()` 调 `onAgentCreated` 并强制一次 `manager.onToolsChange()`，覆盖 manager 订阅 `tools/change` 之前桥已经就绪的窗口。
4. **持久化用 DSH 原生 `storage-domain`，但 schema 定义完全内联**。新增 `cangzhi_session` domain（`per-record` 布局，表 `workspaces` / `policies`），每次 `put`/`delete` 在介质接受后才 resolve；Host 重启后 domain 重新装载即恢复会话间状态。`ctx.get('storage')` 不可用时降级为进程内存 store（明确告警：重启不保留），绝不依赖浏览器 localStorage（localStorage 仅用于 UI 显示恢复，不是安全边界）。`src/host/storage-open.mjs` 把 `defineDomain` / `domainTable` / 迷你 `z`（`z.string()` 与 `z.enum([...])`）全部内联进 bundle，**不依赖** `@deepseek-ai/dsh-storage-domain` 与 `zod` 在运行时的解析路径，避免文件挂载时 `ERR_MODULE_NOT_FOUND`；`@deepseek-ai/dsh-storage` 仍为 peerDependency（`ctx.storage` hub 由 DSH 注入）。
5. **客户端控制端点显式携带 `sessionId`**。`GET/POST /workspace` 与 `GET/POST /session-policy` 都以 `sessionId` 为键；未带 `sessionId` 时 workspace 查询/改动返回 400，仅 `processDefault:true` 的明确标注才允许进程级变更。客户端 `syncModelWorkspace(slug, sessionId)` 仅在持有 sessionId 时 POST；管理中心（无会话绑定）不再向任何模型工作空间写进程级状态。Popover / Dock / 会话头 `useEffect` 依赖补齐 `sessionId`，切会话立刻重载；load 路径先读 `/_cangzhi-plugin/workspace?sessionId=...`，只在 Host 返回 `bound:false` 时回退到 cangzhi cookie 并主动 pin。
6. **MCP 调用语义保留**：`invokeCangzhiMcp` 默认 120_000ms 墙钟 timeout（`exec.signal` 仍可优先取消），JSON / SSE 双路响应解析，`isError` / JSON-RPC `error` 抛错，`structuredContent` 透传；4xx/5xx 立即丢弃缓存的 `Mcp-Session-Id`。
7. **入站 `x-cangzhi-workspace` 信任边界**：回环代理对入站 header 做 slug 正则校验，畸形值直接拒绝；未带 header 的请求回退到 `activeWorkspaceSlug`，仅作为进程级 `cangzhi-mcp` bridge 的明确降级默认。

## 折衷

- 采用「作用域工具覆盖」而非每会话 spawn 一个完整 MCP client：前者在每次执行解析工作空间（天然满足「切换立即生效」与并发隔离），且避免每会话一条 streamable-http 连接与重连；代价是 override 需经插件自有回环代理转发 MCP `tools/call`，并保证 schema/结果/取消语义与通用 bridge 一致（复制全局注册的 `parameters`/`output`/`present*`，`execute` 返回与 bridge 相同 `{content, structuredContent?}` 形状、`isError` 抛错、`exec.signal` 透传取消）。
- `storage-domain` / `zod` 在第一轮曾作为 peerDependency 由 DSH 运行时提供；第二轮复核发现这在 `file:` 挂载场景下不可解析，已改为内联实现，runtime 不再依赖这两个包。

## 验收映射

Codex 集成修正：会话加载只读取 Host 空间，不使用 Cookie 自动写入 pin；工作台请求显式携带该空间。开关刷新从 Host 读取。全局工具限制在开启会话也保留，scoped 覆盖注册失败时禁止回落；重连比较工具定义身份。MCP 超时覆盖响应正文读取，协议头为 `mcp-protocol-version`。这些修正优先于上文第二轮记录中的旧描述。

实机验证：3090/3091 临时 Host 启动成功、persistence=domain；测试会话 off 策略在 Host 重启后保持。浏览器自动化导航未完成，不能据此宣称浏览器并发和证据预览已验收。

- 并发 A/B 各用各自工作空间：`session-state` / `session-manager` 测试断言每次执行 wire 上的 `x-cangzhi-workspace`，并使用 `ctx.tools.execute` 真实管线覆盖 A/B 并发 `Promise.all`。
- 父→子继承、子→父隔离、清除子 pin 恢复继承：纯解析 + manager 测试。
- 刷新 / 恢复 / Host 重启保持：`serializeState`/`deserializeState` 往返与 `storage-domain` 持久化。
- 无 sessionId 降级：解析返回 `bound:false`；override 无执行会话时拒绝而非回落。
- 能力开关持久化：`setPolicy` 写入 store，manager 据此追加/移除 restrict 与覆盖。
- bridge 先于 manager / 桥重连 / 桥消失：manager 的 `cangzhiSignature` 比对 + 主动 `onAgentCreated` + 首次 `onToolsChange` 保证任意顺序下的覆盖一致性。
- MCP 120s timeout / 信号透传 / SSE / session id 失效：4 项独立单元测试。
- 客户端 cookie 跨会话覆盖：已被先读 Host 状态、依赖补齐、`switchWorkspace` 改写顺序解决。
