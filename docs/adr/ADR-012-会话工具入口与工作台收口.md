# ADR-012：会话工具入口与工作台交互收口

- 日期：2026-09-09
- 状态：已采纳，代码完成、浏览器待验收

## 背景

藏知当前占用 `conversation.input.dock`，以全宽卡片显示在输入框上方，并同时在会话头、Popover、右侧工作台和 DSH 设置页提供部分重叠的控制。入口多、状态分散，而且 Popover 与右侧工作台使用两种不同的空间模型。工作台最大宽度固定为 760px，在宽屏上不足以舒适预览多列表格和文档。

DSH `0.1.5-alpha.1` 已提供 `conversation.input.left`，其语义是输入框工具行左侧的紧凑业务控件，位置与指令、附件和计划控件一致。

## 决策

1. 会话主入口迁到 `conversation.input.left`，显示紧凑的藏知按钮、连接状态和能力开关状态；点击直接打开右侧工作台，不再打开 Popover。
2. 移除 `conversation.input.dock`、`conversation.hero.context` 和 `conversation.session.header.actions` 三个重复入口。侧栏入口继续作为全局管理中心入口。
3. 工作台统一承载会话控制与资料操作：
   - 顶部会话控制区提供“本对话使用藏知”、当前知识空间、连接/断开与登录；
   - 保留资料、预览、当前对话视图；
   - 新增设置视图，复用 DSH 设置页的连接设置组件，不复制状态或保存逻辑。
4. 工作台只保留连续拖拽，不恢复窄/标准/宽或全屏按钮。桌面最小宽度 420px，默认 640px，动态最大宽度为 `min(1200px, viewport - 360px)`；移动端保持全宽。宽度继续写入本地偏好。
5. 打开结构化证据时强制进入预览视图；普通工具栏入口进入上次视图。空间和能力开关仍以 Host 的会话状态为准，浏览器偏好不成为隔离边界。

## 取舍

- 优点：输入区域更接近 DSH 原生工具体验；只有一个会话控制面；宽屏预览空间明显增加；连接设置继续使用现有 SettingsScope、锁定与重启提示语义。
- 代价：旧 DSH 若没有 `conversation.input.left` 将不再获得输入区降级入口；本适配器以当前 DSH 版本为目标，侧栏管理入口仍可用。
- 全局管理中心包含服务器状态、空间和分类等大范围管理能力，本轮不将其全部塞入会话工作台，避免把对话工具再次变成大型后台。

## 验收

- 输入框上方没有藏知全宽卡片，工具行出现紧凑入口。
- 打开入口后不出现 Popover，会话开关、空间、登录和连接操作均可在工作台完成。
- 工作台可拖至 760px 以上且不把主对话区压到 360px 以下；刷新后宽度恢复。
- 证据点击进入正确预览，数据表分页、Markdown、PDF/Word 和纯文本路由不退化。
- 关闭藏知后下一次模型步骤看不到 `mcp__cangzhi__*`，切换空间继续按 `sessionId` 隔离。
