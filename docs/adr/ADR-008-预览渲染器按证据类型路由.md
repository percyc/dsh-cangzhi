# ADR-008：预览渲染器按证据类型路由

日期：2026-09-01  
状态：已接受

## 背景

工作台过去主要根据 `context_markdown` 是否存在来选择渲染方式。数据表证据也可能
带 Markdown 形式的摘要，PDF / Word 抽取文本也可能包含 `#`、`|` 等符号，
因此“有 Markdown 字符就用 Markdown 渲染”会混淆文档类型，导致表格显示原始
管道符，或普通文档被误当成 Markdown。

藏知证据接口已返回 `evidence_type`、`document_type`、`dataset` 和
`table_location`，这些结构化元数据应当是渲染决策的权威来源。

## 决策

1. 新增纯函数路由层 `preview-routing.mjs`，将“识别内容类型”与 React 渲染分离。
2. 版本绑定证据按以下优先级分类：
   - `dataset` / `table_location` / 数据行载荷：数据表渲染器；
   - `markdown` / `note`：DSH `MarkdownText` 渲染器；
   - `pdf_word` / `document` / `pdf` / `doc` / `docx`：文档摘要或二进制预览；
   - 无类型的旧载荷才使用保守的 Markdown 内容识别。
3. 普通资料预览同样先看 `content_kind`、`source_type`、`document_type`：
   - 数据表使用分页表格；
   - Markdown / 笔记使用 `MarkdownText`；
   - PDF / Word 使用文档 blob 预览；
   - 其他纯文本使用 `<pre>`。
4. 扩展名只作普通资料的兼容回退，不覆盖服务端元数据。
5. 数据表证据即使尚未取得行数据，也显示数据集摘要，不把 Markdown 管道表当作
表格的主要降级方式。
6. `dataset_catalog` 发现线索先通过版本绑定接口核验数据集身份，然后打开真实
   数据行的分页预览；有 `source_rows` 的精确证据仍只展示本轮实际贡献行。
   两种模式不互相伪装，身份冲突时拒绝用其他数据集代替。

## 结果

- 同一类文档在普通资料和证据入口中遵循一致的路由规则。
- 新增文档类型时，先扩展后端分类与纯函数路由测试，不在 JSX 中散落写死判断。
- 旧历史证据仍可预览，但内容识别仅是兼容逻辑，可能不如新载荷精确。

## 验证

- `tests/preview-routing.test.mjs` 覆盖元数据优先级、数据表优先、旧载荷回退和
  普通资料路由。
- 2026-09-01 全量 80 项 Node 测试、DSH preset 构建、bundle 身份重写、
  `npm run check` 和 `git diff --check` 通过。
- `web` Profile 已刷新；临时 3090 端口返回有效 DSH 页面和插件状态，实际下发的
  bundle 包含新类型路由标记。
- Orca Computer Use 运行时无法加载已安装的 AT-SPI Python 绑定，因此改用
  隔离的 Chrome DevTools Protocol 做页面级验收。DSH 主页、藏知入口、管理中心和新
  bundle 均加载成功，无 ModuleLoader / 注册错误；隔离浏览器不复制用户登录态，
  已登录证据的最终视觉效果仍需在用户会话中确认。
